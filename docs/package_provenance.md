# The manifest's provenance record

`manifest.json` of a package with `schema_version` 4 or later has a `provenance` record. It answers, from the
manifest alone: which shipped files contain generated content, made by which model, from which request, and which
deterministic steps lie between a source and a file. Read it as optional (older packages have none) and test
`schema_version >= 4` before relying on it. Code: `src/antigravity3d/kernel/provenance.py`; the check that holds a
record to its own graph is `provenance.problems`, run by `validate_package` from version 4.

It holds identities and hashes only: no times, no costs, no tokens, no paths on the author's machine. A design or an
image taken from the design record or the image cache records exactly what the run that paid for it recorded, so two
exports of one scene stay byte-identical and a rerun does not change a file's provenance.

## Shape

```json
"provenance": {
  "version": 1,
  "generated_content": true,
  "models": ["gemini-4-carbon", "gemini-nano-banana-2.1"],
  "offline_fakes": false,
  "unrecorded": [],
  "authoring_calls_made": [{"operation": "repair", "model": "...", "role": "...", "request_sha256": "..."}],
  "sources": {
    "design":       {"kind": "model_authored", "model": "...", "role": "builder", "operation": "propose", "candidate": 2,
                     "request_sha256": "...", "scene_sha256": "...", "references": ["style_anchor"]},
    "albedo:paint": {"kind": "model_generated_image", "model": "...", "prompt": "olive drab painted steel",
                     "size": 2048, "variant": "option 2", "image_sha256": "...", "response_id": "..."},
    "ortho":        {"kind": "model_generated_image", "model": "...", "prompt": "...", "size": null,
                     "variant": "<emphasis>", "image_sha256": "...", "response_id": "...", "references": ["style_anchor"]},
    "style_anchor": {"kind": "user_supplied", "sha256": "..."},
    "supplied:tree.glb": {"kind": "user_supplied", "sha256": "...", "bytes": 12345}
  },
  "files": {
    "textures/paint_normal.png": {"derived_from": ["albedo:paint"], "steps": ["prepare_albedo", "derive_pbr"],
                                  "generated_content": true, "generated_by": ["gemini-nano-banana-2.1"]},
    "Prop.glb": {"derived_from": ["design", "textures/paint_albedo.png", "..."], "steps": ["glb_writer", "contact_face_removal", "uv_unwrap"],
                 "generated_content": true, "generated_by": ["..."]}
  }
}
```

* `sources`: the roots. `design` is the scene; `albedo:<material>` a generated image (the winner of its tournament; its
  hash is of the raw generated PNG, before the deterministic de-lighting); `ortho` the blueprint (`ortho.png`);
  `style_anchor` and `supplied:<file name>` are the user's (by hash; a file's name, never its folder).
* `kind` of a source: `model_authored` (an authoring model answered; `request_sha256` is the hash of the whole
  request, the key of the design record without its prefix; `scene_sha256` the hash of the scene as authored),
  `model_authored_in_session` (a native session: the conversation's agent edited the scene, `model` is null because the
  studio does not see it), `template` (the offline deterministic author: no model), `model_generated_image`,
  `offline_fake_image` (the offline stand-in: `model` says so, it is not counted as generated by a model),
  `user_supplied`, and `unrecorded` (a source the pipeline that wrote the package did not record).
* `files`: every file in `files` except `manifest.json`. `derived_from` lists source ids and other shipped files;
  `steps` the deterministic code between them; `generated_content` is true (a model made part of it), false (none did)
  or null (a source of it is `unrecorded`: never read null as no); `generated_by` the model ids.
* package level: `generated_content` (true if any file is; null if none is and some are unknown), `models`,
  `offline_fakes`, `unrecorded` (the source ids), and `authoring_calls_made`: every repair request made while the
  design was refined. Whether each repair was kept is not recorded (the pipeline rolls some back), so these are calls
  made, not a claim about what shaped the files.

## An edited asset

`agy3d edit` (``dags/edit_asset.py``) changes a shipped asset with one patch. The new package's record carries the
earlier record's sources (the design, the images: an edit generates none) and adds `edit:<n>` for each edit, which
every file made from the design also derives from: `{"kind": "model_authored", "operation": "edit", "model", "role",
"request_sha256"}` for an edit a model made, `{"kind": "user_supplied", "operation": "edit", "patch_sha256"}` for a patch
the developer supplied (`--patch`). `authoring_calls_made` lists the edit's authoring calls after the earlier ones. The
manifest's `edits` lists each edit (number, instruction, ops, parts touched, the previous manifest's hash), so a design
with two authoring calls behind it says so.

## What the design was made from

`design_inputs` (every `agy3d prop` package from round five on): the brief as the user wrote it, the art direction's
id (or null) and the whole budget the design was made for. They are what an edit of the package alone needs (the run
folder's report has them too). It is the user's own text, about the asset, the same on every run of it.

## What is absent

* An offline run (`--offline`): `design.kind` is `template`, images are `offline_fake_image` with `model` "offline
  fake image backend", `generated_content` is false and `offline_fakes` true.
* A package built from an imported mesh only (`mesh_ref` nodes): the mesh is `supplied:<name>` (`user_supplied`), and
  a scene that only places it is `design.kind` `user_supplied` in a native session.
* A native session: no `candidate`, `request_sha256` or `scene_sha256` (the conversation's agent authored the scene);
  an albedo is credited to the image model only while the material still uses the maps `forge_pbr_material` wrote,
  otherwise it is `unrecorded`.
* Not covered: `agy3d kit` and `agy3d sanitize` write no `manifest.json` (their outputs are USD, GLB and a report), so
  they have no record. In `agy3d prop`, a material that the pyramid re-textures itself because the speculative
  material step failed is `unrecorded`.
