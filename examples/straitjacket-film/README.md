# How Straitjacket Works: a scroll film

A single scrolling page that shows how [Straitjacket](https://github.com/vamsiramakrishnan/straitjacket) works by
following one real log through it. The page is a "scroll film": one fixed three.js scene whose whole state is
computed from how far you have scrolled, with the explanation in ordinary HTML on top.

It is here as an example of this repository's three.js path used on a real site: the five physical props in the
scene are built from scripts by the antigravity-3d plugin, checked by it for three.js and for Godot, and loaded by
the page as plain GLB files.

```
site/           the page; any static file server can serve it as it is (no build step, nothing from a CDN)
assets-src/     one build script per prop, and how to rebuild them
tools/          make_data.py   numbers and the 20,001 lines, from Straitjacket's receipts
                build_page.py  site/index.html from site/film.html
                check_site.py  what must be true before publishing
                bake_contact.py  the soft shadow under each prop, baked in Blender
                shots.js       screenshots at fixed moments of the film, headless
```

## Look at it

```bash
cd examples/straitjacket-film/site && python3 -m http.server 8000     # then open http://localhost:8000/
```

## How it is put together

**The scroll.** Each chapter is a tall section. Film time `T` is the chapter's index plus the share of it that has
passed the top of the window (`js/chapters.js`). The scene never animates on its own: `js/scene/tracks.js` turns `T`
into a camera pose and a handful of numbers between 0 and 1 (how far the flood has run, how far the capture has run,
and so on), and the scene draws exactly that. Scrolling back, jumping from the chapter rail and resizing are correct
for the same reason, and a moment of the film can be asked for by number, which is how `tools/shots.js` takes its
pictures. Lenis smooths wheel input on desktop; touch scrolls natively.

**The lines.** Straitjacket's benchmark log is generated by `evals/field_needle.py` in its repository.
`tools/make_data.py` rebuilds it with the same algorithm and refuses to continue unless the result has the SHA-256
recorded in Straitjacket's receipt and the template counts printed in its checked-in digest. Each of the 20,001
slabs in the scene is one line of that log: its length is the line's length, its bay in the store is its template.
They are one instanced mesh; every flight is computed in the vertex shader from one number per transition, so the
processor does no per-line work while you scroll.

**The words and numbers.** `site/film.html` holds all of them, each number marked with the place in
`site/data/film.json` it comes from. `tools/check_site.py` fails if the page and the receipts disagree.

**The props.** `assets-src/*.py` are scripts for the plugin's script path (`from agy3d import Asset`). The plugin
builds each one, paints its surface from the geometry, and checks the result; see `assets-src/README.md` for the
commands and the measured sizes.

**The light.** One key light with a shadow map, and under each prop a contact shadow baked in Blender
(`tools/bake_contact.py`): the soft dark seat that a real-time light does not give.

**When there is no WebGL, or motion is not wanted.** Without WebGL or without JavaScript the page is an ordinary
article with Straitjacket's own diagrams in place of the scene. With "reduce motion" set, the scene does not travel:
it changes from one chapter's resting picture to the next.

## Rebuild

```bash
python3 tools/make_data.py /path/to/straitjacket site/data     # needs a checkout of Straitjacket
python3 tools/build_page.py
python3 tools/check_site.py
node tools/shots.js --out /tmp/film-shots --sheet                # needs Playwright and Chromium
blender -b --factory-startup -P tools/bake_contact.py -- site/assets
```
